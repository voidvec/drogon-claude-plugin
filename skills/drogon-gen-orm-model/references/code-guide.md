# drogon-gen-orm-model 实现指南

所有命令行参数与 model.json 字段均按 drogon v1.9.13 源码核对（`drogon_ctl/create_model.cc`、`drogon_ctl/create_model.h`、`drogon_ctl/templates/model_h.csp`）。

## 1. 参数验证

生成前逐项检查，缺一即终止并报告，不猜测默认值：

- `db_type` 只能是 `postgresql` / `mysql` / `sqlite3`（create_model.cc:964-968，其他值报 "Does not support"）。
- PG/MySQL：`dbname` 与 `user` 必填，为空时工具 exit(1)（create_model.cc:1014-1028）；`host` 默认 `127.0.0.1`；**MySQL 的 `port` 默认值同样是 5432**（create_model.cc:1125），MySQL 必须显式写 `"port": 3306`。
- SQLite3：`filename` 必填（create_model.cc:1230-1236）。
- 密码键 `passwd` 与 `password` 都接受，`passwd` 优先（create_model.cc:1029-1033）。
- 数据库账号需有表读权限：PG 权限不足时逐表打印 "please check privileges on the table"（create_model.cc:254-257）。
- `model.json` 必须存在于模型目录内，缺失/不可读/JSON 格式错误分别报错退出（create_model.cc:1327-1366）。

## 2. drogon_ctl create model 用法（源码核对）

命令形式：`drogon_ctl create model [选项] <模型目录>...`，`<模型目录>` 内含 `model.json`。

### 命令行参数（全部在 create_model.cc:1369-1426 handleCommand 解析）

| 参数 | 作用 | 源码位置 |
|------|------|----------|
| `--table=<表名>` | 只为指定单表生成模型 | create_model.cc:1379-1385 |
| `-f` | 强制覆盖，跳过 y/n 交互确认 | create_model.cc:1387-1394 |
| `-o <目录>` / `--output <目录>` | 输出目录与 model.json 所在目录分离 | create_model.cc:1395-1409 |
| `--clear-output` | 生成前先删除输出目录内所有 .h/.cc（隐含 -f，删除前仍有一次 y/n 确认） | create_model.cc:1411-1420, 976-1007 |

**与网上常见说法不符（以源码为准）**：`-a`、`--conns`、`--r`、`--restful` 等参数**并不存在**，连接串也不能从命令行传入。全库生成、关系映射、restful 控制器全部由 model.json 配置驱动：

- **全库生成**：`"tables": []`（空数组或缺省）时枚举库中全部表（create_model.cc:1075-1082）；填表名数组则只生成指定表，表名统一转小写（create_model.cc:1088-1091）。
- **关系映射（--r 的真实形态）**：model.json `relationships` 节；且 v1.9.13 会**自动检测外键**——PG/MySQL/SQLite3 分别查 information_schema / `PRAGMA foreign_key_list`，自动追加双向 "has one" 关系，用户显式配置优先（create_model.cc:181-218、454-487、688-713、899-917）。
- **restful 控制器（--restful 的真实形态）**：model.json `restful_api_controllers` 节 `enabled: true`（create_model.cc:1428-1605）。

### model.json 关键字段

连接：`rdbms` / `host` / `port` / `dbname` / `user` / `passwd`（或 `password`）/ `client_encoding`；PG 专用 `schema`（默认 `public`，非 public 时生成代码多嵌套一层同名 namespace，create_model.cc:241-244）。

关系映射（字段校验见 create_model.h:211-281；完整样板见 templates/model_json.csp）：

```json
"relationships": {
  "enabled": true,
  "items": [{
    "type": "has many",
    "original_table_name": "users",
    "original_key": "id",
    "target_table_name": "orders",
    "target_key": "user_id",
    "enable_reverse": true
  }]
}
```

`type` 取 `has one` / `has many` / `many to many`；`many to many` 还需 `pivot_table: {table_name, original_key, target_key}`；可选 `original_table_alias` / `target_table_alias` 改生成方法名。列值读写转换用 `convert` 节（`after_db_read` / `before_db_write` / `includes`，create_model.h:138-209）。

restful 控制器节：`enabled`、`resource_uri`（默认 `/*`，`*` 替换为表名并转小写）、`class_name`（默认 `Restful*Ctrl`，可含 `::` 命名空间）、`filters` 数组、`db_client`（`name`/`is_fast`，须与应用 config 一致）、`directory`（默认 `controllers`）、`generate_base_only`（true 时只生成 `*Base` 类，避免覆盖自定义子类，create_model.cc:1552-1575）。

### 完整命令示例

PostgreSQL（authforge 生产模式，model.json 放在 src/models/ 下）：

```bash
mkdir -p src/models        # 先把写好的 model.json 放入该目录
echo "y" | drogon_ctl create model src/models          # 全库（y 应答覆盖确认）
drogon_ctl create model --table=users src/models       # 单表（确认仍需 y，或加 -f）
drogon_ctl create model -f -o build/gen src/models     # model.json 与输出目录分离
```

MySQL：model.json 改 `"rdbms": "mysql"` 并**显式写 `"port": 3306`**，命令完全相同。SQLite3：改 `"rdbms": "sqlite3"` + `"filename"`。

## 3. 生成物结构与约定

每张表生成 `<ClassName>.h` + `<ClassName>.cc`（create_model.cc:491-497）。类名由表名按下划线转驼峰得到（`pay_order` → `PayOrder`，create_model.h:47-79）。文件头带 `DO NOT EDIT. This file is generated by drogon_ctl`（templates/model_h.csp:7）。

- 命名空间 `drogon_model::<dbname>`（PG 非 public schema 再嵌套一层）。
- 表元信息是**静态成员而非宏**——旧资料常写的 `TABLE_NAME`/`primaryKey` 宏在本版本不存在，以源码为准：`Cols::_xxx` 列名常量、`tableName`、`primaryKeyNumber`、`primaryKeyName`、`PrimaryKeyType`（单主键=列类型；多主键=`std::tuple`，且 sqlite3 多主键会清除自动增量标记，create_model.cc:887-892）。
- 每列生成 `getValueOfXxx()`（NULL 返回默认值）/ `getXxx()`（shared_ptr）/ `setXxx()`，另有 `toJson()`、`validateJsonForCreation/Update()`；关系表生成 `get<目标类>(clientPtr)` 同步版与 `(clientPtr, rcb, ecb)` 回调版（model_h.csp:209-306）。
- 类内 friend 声明使 `Mapper<T>` / `BaseBuilder` / `CoroMapper` 可访问私有成员（model_h.csp:308-315）。类型映射规则在工具内部（PG `numeric`→`std::string`、`timestamp`→`trantor::Date`、`bytea`→`std::vector<char>`；MySQL `unsigned`→`u` 前缀、`tinyint`→`int8_t`，create_model.cc:273-329、584-648）——这是必须生成、不能手写的根本原因。
- **定制纪律**：业务逻辑写在独立 Repository/服务层（authforge 的 Postgres*Repository 模式）或包装类中，绝不改生成文件。改表后重跑生成命令；authforge 流程为"备份到 models_backup/（gitignore）→ 重生成 → 头文件 mv 到 include/ 目录"（scripts/backend/generate-models.sh）。

## 4. CMake 集成

**模式 A：add_custom_command 自动生成**（表结构频繁变动、CI 可连库时）。以生成文件为 OUTPUT，`-f` 免交互，DEPENDS 写 model.json：

```cmake
file(GLOB MODEL_SRCS ${CMAKE_CURRENT_SOURCE_DIR}/src/models/*.cc)
add_custom_command(OUTPUT ${MODEL_SRCS}
    COMMAND drogon_ctl create model -f ${CMAKE_CURRENT_SOURCE_DIR}/src/models
    DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/src/models/model.json)
```

**模式 B（authforge / pay-plugin 生产模式）：脚本手动生成 + OBJECT library 隔离**。生成物单独成目标——不背第一方 WERROR 门槛、不计入覆盖率；警告按文件级压制而非降整个目标的警告级（authforge 用 `set_source_files_properties(... COMPILE_OPTIONS "/wd4100")`）：

```cmake
add_library(xxx_models OBJECT src/models/A.cc src/models/B.cc)
target_include_directories(xxx_models PRIVATE src/models include)
target_link_libraries(xxx_models PRIVATE Drogon::Drogon)
target_sources(xxx PRIVATE $<TARGET_OBJECTS:xxx_models>)   # 对象并入第一方库
```

**orm_compat.h codecvt shim（MSVC ≥ 19.43 / C++20 必需）**：drogon 内部依赖已弃用的 `std::codecvt_utf8_utf16` 做 UTF-8 校验，C++20 与新版 MSVC 下生成代码编译告警甚至失败。pay-plugin 方案：`orm_compat.h` 在 `__cplusplus >= 202002L && !defined(_MSC_VER)` 时于 `std` 内提供 `codecvt_utf8_utf16` 最小实现；MSVC 侧靠 `_SILENCE_CXX17_CODECVT_HEADER_DEPRECATION_WARNING` 压弃用告警。用 force-include 注入每个编译生成代码的翻译单元——**include 生成头的第一方目标同样要注入**（生成头传递性暴露 codecvt 面）：

```cmake
if(MSVC)
    target_compile_options(xxx_models PRIVATE /FI"orm_compat.h" /utf-8)
    target_compile_definitions(xxx_models PRIVATE
        _SILENCE_CXX17_CODECVT_HEADER_DEPRECATION_WARNING _CRT_SECURE_NO_WARNINGS)
else()
    target_compile_options(xxx_models PRIVATE -include orm_compat.h)
    target_compile_definitions(xxx_models PRIVATE _SILENCE_CXX17_CODECVT_HEADER_DEPRECATION_WARNING)
endif()
# 对第一方目标（其源文件 include 生成头）重复同样一段 /FI / -include
```

## 5. 禁止模式清单

| 反例 | 说明 |
|------|------|
| 手写模型类替代生成 | 类型映射分支繁多（numeric→string、unsigned→u 前缀、timestamp→Date），手写必错；且没有 friend Mapper 声明，Mapper<T> 无法访问私有成员 |
| 直接编辑生成 .h/.cc | 文件头明示 DO NOT EDIT；重生成直接覆盖，手改必丢（authforge CMake 注释原话 "regeneration would lose any hand-edit"）；定制一律走包装/Repository 层 |
| 把生成目录纳入手工测试覆盖或 WERROR 门槛 | pay-plugin：模型 OBJECT 库不挂 WERROR、不计 gcov；authforge：按源文件压警告，绝不为此降低整个目标的警告级 |
| 忘记把模型 .cc 加进 CMake | `Cols::_xxx` 等静态常量与 Mapper<T> 显式实例化都定义在生成 .cc 里，漏编即 undefined reference |
| restful 自定义子类不设 `generate_base_only` | 重生成时会覆盖 `*Base.h/.cc`，并对已存在的自定义子类触发覆盖确认（create_model.cc:1552-1575），脚本化时易误删自定义代码 |

## Mapper<T> 最小示例（回调式）

```cpp
#include <drogon/orm/Mapper.h>
using namespace drogon::orm;
using PayOrder = drogon_model::pay_test::PayOrder;

Mapper<PayOrder> mapper(app().getDbClient());            // 构造见 Mapper.h:124
mapper.insert(order,                                     // 插入（Mapper.h:562，回填自增主键）
    [](PayOrder r) { LOG_INFO << "id=" << *r.getId(); },
    [](const DrogonDbException &e) { LOG_ERROR << e.base().what(); });
mapper.findOne(Criteria(PayOrder::Cols::_order_no,
                        CompareOperator::EQ, orderNo),   // 查询（Mapper.h:501）
    [](PayOrder r) { /* 恰好命中一行 */ },
    [](const DrogonDbException &e) { LOG_ERROR << e.base().what(); });
```

回调类型：`SingleRowCallback = std::function<void(T)>`（Mapper.h:254）；`ExceptionCallback = std::function<void(const DrogonDbException &)>`（DbClient.h:41）。行数不为一时 `findOne` 走异常回调（UnexpectedRows）。
